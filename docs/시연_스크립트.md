# 책숲 AI 사서 — 강연 시연 스크립트

> 화면: `demo/index.html` (서버: `demo/server.py`) · 시나리오 원본: `demo/scenarios.json`
> 모델: 실제 `gpt-6-luna` (오프라인 모드 없음). 예상 소요: 시나리오 8개 약 12~15분 (모델 응답 시간에 따라 달라짐)

## 1. 실행 방법

터미널 1개에서 프로젝트 루트로 이동해 실행한다.

```bash
source .venv/bin/activate
```

```bash
read -rs OPENAI_API_KEY && export OPENAI_API_KEY
```

```bash
python demo/server.py
```

브라우저에서 `http://127.0.0.1:8000`을 연다. 다른 포트는 `--port 8001`처럼 지정한다.

- 서버는 이 컴퓨터에서만 접속된다 (`127.0.0.1`). 강연장 다른 기기에서 접속하게 하려면 `--host 0.0.0.0`을 쓰되, 공용 네트워크에서는 권하지 않는다.
- API key는 환경변수로만 읽는다. 화면, 응답, 서버 로그에 key가 나오지 않으며 오류도 종류(예외 이름)만 표시한다.
- trace는 `runs/demo/trace.jsonl`에 쌓인다 (git에는 올라가지 않는다).

## 2. 화면 구성

| 영역 | 설명 |
|---|---|
| 왼쪽 | 시연 시나리오 8개. 누르면 대화와 추적을 비우고 **새 대화**로 질문을 보낸다. 연체료·재고는 유지된다. |
| 가운데 | 대화. 아래 입력창에서 직접 질문하면 **같은 대화로 이어진다**. |
| 오른쪽 위 | 실행 추적. 도구 호출이 **끝나는 순서**로 쌓인다. 색 배지는 supervisor(보라), rules(파랑), catalog(초록), circulation(주황). |
| 오른쪽 아래 | 회원 카드(M-0001, M-0003, M-0008)의 연체료와 대출 수. 값이 바뀌면 잠깐 강조된다. |
| 승인 창 | `waive_fee`가 실행 직전에 멈추면 뜬다. 승인 / 수정 후 실행 / 거절. |
| 헤더 | `발표자 노트 (N)`: 시나리오별 설명 멘트와 볼 것을 왼쪽 아래에 표시한다. `전체 초기화`: 연체료, 재고, 대화, 추적을 처음 상태로 되돌린다. |

> 추적에서 안쪽 agent(예: `search_loan_rules`) 줄이 바깥(`ask_rules_agent`)보다 **먼저** 나오는 것은 정상이다. 도구가 끝나야 기록되기 때문이다. 이것이 "agent가 도구로 연결된 구조"를 설명하는 좋은 순간이다.

## 3. 시연 순서와 멘트

### 오프닝 (1분)
"작은 동네 도서관 '책숲'의 AI 사서입니다. 질문을 supervisor가 받아서 규정, 검색, 대출 처리 담당에게 나눠 주고, 연체료 면제처럼 위험한 일은 사서가 승인해야 실행됩니다. 오른쪽은 AI가 실제로 어떤 도구를 불렀는지 보여 주는 기록입니다."

### S1. 규정 질문 (RAG) — 1분
- 질문: 신규 회원은 몇 권까지 빌릴 수 있나요?
- 멘트: "규정 파일을 조 단위로 잘라 BM25로 검색합니다. 답에 근거 조항(제2조)이 붙습니다."
- 볼 것: `search_loan_rules` → `ask_rules_agent` 순서, 답의 "3권", "제2조"

### S2. 여러 규정에 걸친 질문 — 1분
- 질문: 신규 회원인데 처음에 몇 권… 독서 모임 혜택은?
- 멘트: "대출 규정과 시설 규정이 같이 필요합니다. 한 agent가 topic별 도구를 둘 다 불러야 합니다."
- 볼 것: `search_loan_rules`와 `search_facility_rules` 둘 다, 답의 제2조와 제15조

### S3. 두 agent 협업 — 1.5분
- 질문: 『기후의 시간』 지금 빌릴 수 있나요? 빌릴 수 없으면 예약 규정도…
- 멘트: "supervisor가 catalog에게 재고를, rules에게 예약 규정을 물어 합칩니다."
- 볼 것: `ask_catalog_agent`와 `ask_rules_agent` 둘 다, 답의 B008과 제5조

### S4. 도구 오류 → 설명 — 1.5분
- 질문: M-0003 회원인데 B001 책을 빌리고 싶어요.
- 멘트: "이 회원은 연체료 1,500원이 있습니다. 도구는 오류를 삼키지 않고 던지고, middleware가 `[UNPAID_FEE]` 메시지로 바꿔 모델에게 돌려줍니다. 모델은 그걸 회원에게 설명합니다."
- 볼 것: `checkout_books`의 빨간 `error`, 출력의 `[UNPAID_FEE] ... 1500원`

### S5. 연체료 면제 — 승인 (HITL) — 2분 ★하이라이트
- 질문: M-0003 회원이 입원 증빙서를 제출했습니다. 연체료 면제를 처리해 주세요.
- 멘트: "면제는 돈과 관련된 결정이라 AI가 마음대로 못 합니다. 실행 직전에 멈추고 사서에게 묻습니다."
- 순서: 승인 창이 뜨면 **뒤의 M-0003 연체료가 아직 1,500원임을 짚는다** → `승인` 클릭 → 0원으로 바뀌는 순간 강조
- 볼 것: 추적에 `waive_fee`가 승인 후에야 나타남

### S6. 연체료 면제 — 거절 (HITL) — 1.5분
- 질문: M-0008 회원 연체료를 면제해 주세요. 사유는 단골 회원이라서입니다.
- 멘트: "같은 창이 뜨지만 이번엔 거절합니다. 거절된 호출은 실행되지 않습니다."
- 순서: `거절` → 사유 확인 → `거절 확정`
- 볼 것: M-0008은 800원 그대로, 추적에 `waive_fee` 줄이 **없음**, 답에 "거절"

### S7. 정보가 부족한 요청 — 1분
- 질문: 책 세 권 빌리고 싶어요. 처리해 주세요.
- 멘트: "회원 ID가 없으면 도구를 부르지 않고 먼저 묻습니다. 잘못된 대출을 막는 가장 단순한 안전장치입니다."
- 볼 것: 추적이 비어 있음

### S8. 범위 밖 질문 — 1분
- 질문: 오늘 서울 날씨 어때요?
- 멘트: "도서관 일이 아니면 어떤 agent도 부르지 않습니다."
- 볼 것: 추적이 비어 있음

### 클로징 (1분)
"테스트 97개로 규칙을 고정하고, 실제 모델은 20개 질문을 3번씩 돌려 모두 통과하는지(pass^3)로 평가했습니다. 실패한 질문 하나는 trace로 원인을 찾아 prompt를 고쳤습니다." (수치는 최종 평가 결과로 갱신해서 말한다)

## 4. 강연 전 점검 (리허설)

- [ ] `OPENAI_API_KEY`가 설정된 터미널에서 서버가 뜬다 (`python demo/server.py`)
- [ ] 시나리오 8개를 **한 번씩 끝까지** 돌려 본다. 모델 답은 매번 문장이 조금씩 다르다.
- [ ] S5를 한 번 실행하면 M-0003의 연체료가 0이 된다. 다시 시연하려면 **`전체 초기화`**를 누른다.
- [ ] 같은 방식으로 S6도 재시연 전에 초기화한다 (거절은 상태가 안 바뀌지만 대화 맥락이 남는다).
- [ ] 브라우저 확대(⌘ +)로 뒷자리에서 읽히는지 본다. 추적 패널 글씨가 가장 작다.
- [ ] 다크/라이트 모드는 OS 설정을 따른다. 프로젝터에서는 라이트가 대체로 선명하다.
- [ ] 네트워크가 끊겼을 때를 대비해 **백업 자료**를 만든다: 리허설 때의 화면 녹화 또는 스크린샷(특히 S5 승인 창), 그리고 `eval/report.json`, `runs/eval/*.jsonl`
- [ ] 알림, 메신저, 터미널의 API key 입력 화면이 공유 화면에 나오지 않게 한다.

## 5. 문제가 생겼을 때

| 증상 | 대응 |
|---|---|
| 응답이 오래 걸림 (10초 이상) | "reasoning 모델이라 생각하는 시간이 있습니다"라고 말하며 오른쪽 추적이 쌓이는 것을 보여 준다. 추적은 0.5초마다 갱신된다. |
| "처리 중 오류가 발생했습니다 (…)" | 서버 터미널에서 예외 이름을 본다. 네트워크/인증 문제면 다음 시나리오로 넘어가거나 백업 자료를 쓴다. |
| 승인 창이 안 뜨고 바로 답이 나옴 | 모델이 `waive_fee`를 부르지 않은 경우다. 추적에 도구가 있는지 확인하고, `전체 초기화` 후 같은 시나리오를 다시 누른다. |
| S5에서 "면제할 연체료가 없습니다" | 이미 한 번 면제했다. `전체 초기화`를 누른다. |
| 답이 기대와 조금 다름 | 모델이 표현만 다른 경우가 많다. 근거(조항, 도서 ID, 금액)가 맞으면 그대로 진행하고, 틀렸다면 "이래서 평가를 3번씩 돌립니다"로 pass^3 이야기로 연결한다. |
| 화면이 멈춘 것 같음 | 브라우저를 새로고침한다. 서버가 살아 있으면 상태(연체료·재고)는 유지된다. |

## 6. 예상 질문

- **왜 agent를 나눴나요?** 역할별로 도구와 prompt를 작게 유지하면 라우팅과 오류 원인 분석이 쉬워진다. 변경 권한은 circulation_agent만 갖는다.
- **HITL은 어떻게 막나요?** `waive_fee`는 실행 전에 graph가 interrupt되고, 승인/수정/거절 결정이 같은 thread로 돌아와야 이어진다. 거절되면 도구가 실행되지 않는다.
- **환각은 어떻게 줄였나요?** 규정과 도서 정보는 반드시 도구 결과로만 답하게 하고, 숫자·조항·ID를 바꾸지 말라는 규칙을 둔다. 그래도 놓친 사례(C01)는 trace로 찾아 고쳤다.
- **pass^3가 뭔가요?** 같은 질문을 3번 독립적으로 실행해 모두 통과해야 통과로 본다. 한 번 운 좋게 맞히는 것을 걸러 낸다.
