- 질문: M-0003 회원인데 B001 책을 빌리고 싶어요.
- 기준: expected_tools = `ask_circulation_agent` / must_contain = `1500원` / forbidden = `waive_fee`
- trial2 판정: `missing_tools=['ask_circulation_agent'] missing_keywords=['1500원']`

## 4. 원인 분류

| 후보 | 판정 | 근거 |
|---|---|---|
| 도구·store 오류 | 아님 | trial1·3에서 `[UNPAID_FEE] ... 1500원`이 정확히 반환됨 |
| circulation_agent의 처리 오류 | 아님 | trial2에서는 circulation_agent가 아예 호출되지 않음 |
| **supervisor의 잘못된 라우팅** | **원인** | 처리 요청인데 "대출 기간이 질문에 없다"는 이유로 규정 질문으로 바꾸어 rules agent에 보냄 |
| 최종 답이 처리 결과를 대신함 | 결과 | 연체료 1,500원 안내가 전혀 없고, 사용자에게 기간을 되물음 |

핵심: 사용자는 이미 회원 ID와 도서 ID를 말했다. 대출 기간은 선택 정보이고 `checkout_books`의 기본값(14일)이 있어 되물을 필요가 없다. 그런데 supervisor가 "빠진 정보를 먼저 채워야 한다"고 판단해 처리 요청을 규정 질문으로 바꿨다.

### 이번 C01 prompt 수정과의 관계

- 이 실패가 C01 수정(도서 ID·재고 요청 문구 추가)에서 비롯됐는지는 **이 증거만으로 구분할 수 없다.** 수정은 도서 질문의 request와 최종 답 문구에 관한 것이고, trial2의 오류는 "대출 기간"을 규정으로 확인한 것이라 내용상 다른 경로다.
- C14 이력: 1차 전체 평가 `OOO`, critical만 k=1 `O`, 2차 `OXO`. 7번 중 1번 실패라서 prompt에 라우팅 규칙이 모호했던 기존 약점이 우연히 드러났을 가능성이 높지만, 단정하지 않는다.

## 5. 수정 (agents.py의 SUPERVISOR_PROMPT만, 일반 규칙)

새 6번 규칙(기존 6·7번은 7·8번으로):
- 대출·예약·연체료 면제 "처리" 요청에 회원 ID와 도서 ID(면제는 사유)가 있으면 **바로 `ask_circulation_agent`에 맡긴다.**
- 대출 기간처럼 선택 정보가 빠져 있어도 기본값으로 처리되므로 **사용자에게 되묻거나 `ask_rules_agent`로 확인하지 않는다.**
- 처리 가능 여부는 규정 설명이 아니라 **`ask_circulation_agent`의 처리 결과**로 판단한다.

(특정 질문 문자열에 맞춘 정답이 아니라 처리 요청 전반의 라우팅 규칙이다.)
